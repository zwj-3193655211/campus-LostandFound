# 校园失物招领平台 - 代码审查报告

## 1. 审查范围
- 后端：`security`、`system`、`item`、`match`、`verification`、`notification`、`statistics`
- 前端：`router`、`stores`、`views`、`utils`
- 配套：SQL 脚本、启动脚本、现有测试文件、README 与设计文档

## 2. 审查结论
- 项目主业务链路已经基本闭环：登录、发布、审核、匹配、通知、完成申请、实名认证、证件找失主均已有实现。
- 权限边界和 JWT 链路比初始阶段明显更稳，后台管理员与超管边界也已落地。
- 当前最主要的风险已经从“功能不可用”转为“前端测试覆盖偏少、审核状态机仍缺更多边界组合覆盖、部分文档过时”。

## 3. 主要发现

### 3.1 严重问题
1. `DbFixController` 仍然是高危运维入口。
   - 风险：具备清表、改表结构、重建账号等破坏性能力。
   - 当前状态：已增加 `app.db-fix-enabled` 环境开关，默认不会注册；安全配置也仅允许 `SUPER_ADMIN` 访问。
   - 当前测试：已补条件装配可见性测试，验证关闭时不注册、开启时才注册。
   - 剩余风险：仍建议把它视为开发/测试工具，不纳入生产常规能力。

2. 图片上传链路已完成第一轮安全加固，但仍有外部依赖风险。
   - 风险：第三方图床超时、抖动、返回结构漂移仍可能影响上传体验。
   - 当前状态：已补大小、MIME、后缀、URL 结构校验，以及远端失败返回兜底；也新增了单元测试覆盖关键分支。
   - 剩余建议：继续补超时、重试和可观测性日志测试。

3. 审核状态机测试仍偏薄。
   - 当前状态：已补服务层重复审核拦截、通知异常兜底、缺参 `400`、条件原子更新，以及基于 H2 的数据库级并发集成测试。
   - 剩余风险：缺参组合、边界状态和 MySQL 实际并发场景仍可继续细化。
   - 建议：围绕 `VerificationController` 和完成申请审核接口继续补边界组合，并在后续环境补 MySQL 实际并发验证。

### 3.2 高风险问题
1. 前端自动化测试覆盖偏少。
   - 现状：已引入 Vitest，并补了路由守卫与 `401` 清理登录态的最小基线测试。
   - 剩余风险：登录弹窗、管理员页面、发布页等关键交互仍主要依赖人工回归。
   - 建议：继续补最小交互测试，并逐步纳入关键页面的错误提示与权限门禁校验。

2. 打包体积依旧偏大。
   - 风险：首屏加载慢，后台页面与 Element Plus 相关产物体积较重。
   - 现状：`ui-vendor` 产物仍超过 1 MB。
   - 建议：继续做按需引入、细化 chunk、延迟加载低频后台页。

### 3.3 中风险问题
1. `docs/project-design.md` 与真实实现存在偏差。
   - 例如：旧文档中的物品状态、模块结构、测试能力与当前代码不完全一致。
   - 建议：将其保留为“设计基线”，另外新增“实现架构文档”承接真实状态。

2. 启动与数据库迁移依然对本地环境较敏感。
   - 风险：MySQL 密码、旧库结构、脚本路径和编码问题仍可能在新机器上复现。
   - 建议：补部署与故障排查文档，并优先采用显式迁移脚本。

## 4. 当前优势
- 后端权限矩阵已有自动化测试覆盖。
- JWT 过滤器已验证 access token 限制与数据库实时角色校验。
- 物品状态、完成申请、实名认证和证件匹配等业务链路已经从“概念设计”落成到可运行实现。
- 前后端主要接口、启动脚本、数据库基线都已形成基本闭环。

## 5. 建议优先级

| 优先级 | 建议 |
|---|---|
| P0 | 为审核状态机补边界状态、缺参组合和 MySQL 实际并发测试 |
| P1 | 为图片上传链路补超时、重试和可观测性测试 |
| P1 | 扩展前端 Vitest 覆盖，优先补登录弹窗与管理员页面最小交互测试 |
| P2 | 继续优化前端 chunk 体积 |
| P2 | 维护设计稿与实现文档的边界，避免再次失真 |

## 6. 本轮处理结果
