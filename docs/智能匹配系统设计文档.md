## 1. 系统概述

### 1.1 项目背景

校园失物招领平台旨在帮助师生快速找回遗失物品。传统的失物招领方式效率低下，用户需要在大量的失物和招领信息中人工查找匹配项。本系统通过**智能匹配算法**，自动分析寻物启示与失物招领信息，为用户推荐最可能的匹配结果。

### 1.2 匹配系统定位

智能匹配系统是本项目的**核心亮点功能**，通过多维度加权评分算法，综合考虑物品的类别、地点、时间、品牌、颜色、序列号等多个特征，计算寻物启示与失物招领之间的匹配程度。

### 1.3 技术架构

| 层级 | 技术选型 | 说明 |
|------|----------|------|
| 后端框架 | Spring Boot 3.2.0 | 核心业务逻辑处理 |
| 数据访问 | MyBatis Plus | 数据库操作与ORM映射 |
| 精确计算 | BigDecimal | 避免浮点精度问题 |
| 时间处理 | Java 8+ Time API | LocalDateTime时间计算 |

### 2.2 核心代码实现

**匹配服务入口** - `MatchingServiceImpl.java`

```java
@Override
@Transactional
public void match(Long itemId) {
    Item item = itemRepository.selectById(itemId);
    if (item == null) {
        log.warn("物品不存在: {}", itemId);
        return;
    }

    // 确定目标类型：LOST → FOUND，FOUND → LOST
    String targetType = ItemConstants.Type.LOST.equals(item.getType())
        ? ItemConstants.Type.FOUND
        : ItemConstants.Type.LOST;

    // 查找候选匹配物品
    List<Item> candidates = findCandidates(item, targetType);
    log.info("物品{} 找到候选匹配 {} 个", itemId, candidates.size());

    // 计算每个候选的匹配分数
    List<ScoredCandidate> scored = new ArrayList<>();
    for (Item candidate : candidates) {
        BigDecimal score = calculateScore(item, candidate);
        if (score != null && score.compareTo(BigDecimal.ZERO) > 0) {
            scored.add(new ScoredCandidate(candidate, score));
        }
    }

    // 按分数降序排序，保留前20名
    scored.sort(Comparator.comparing(ScoredCandidate::score).reversed());
    int topK = Math.min(20, scored.size());

    // 生成匹配记录
    for (int i = 0; i < topK; i++) {
        ScoredCandidate candidate = scored.get(i);
        saveMatch(item, candidate.item(), candidate.score());
    }
}
```

## 3. 候选物品筛选

### 3.1 筛选条件

在执行匹配算法之前，系统首先筛选符合条件的候选物品：

| 筛选条件 | 说明 | 代码逻辑 |
|----------|------|----------|
| 物品类型 | 寻物(LOST) ↔ 招领(FOUND) 必须配对 | `wrapper.eq(Item::getType, targetType)` |
| 物品状态 | 仅匹配已审核通过的物品 | `wrapper.eq(Item::getStatus, ItemConstants.Status.APPROVED)` |
| 排除自身 | 不匹配自己 | `wrapper.ne(Item::getId, item.getId())` |
| 序列号优先 | 有序列号时按序列号精确匹配 | 序列号非空时仅匹配同序列号物品 |
| 类别过滤 | 无序列号时按类别匹配 | `wrapper.eq(Item::getCategory, item.getCategory())` |
| 时间窗口 | ±60天内 | `wrapper.between(Item::getFoundTime/LostTime, start, end)` |

### 3.2 序列号优先策略

```java
String serial = item.getSerialNumber();
if (serial != null && !serial.isBlank()) {
    // 有序列号：仅匹配同序列号的物品
    wrapper.eq(Item::getSerialNumber, serial.trim().toUpperCase());
} else {
    // 无序列号：按类别 + 时间窗口匹配
    if (item.getCategory() != null) {
        wrapper.eq(Item::getCategory, item.getCategory());
    }

    LocalDateTime refTime = ItemConstants.Type.LOST.equals(item.getType())
        ? item.getLostTime()
        : item.getFoundTime();

    if (refTime != null) {
        LocalDateTime start = refTime.minusDays(60);
        LocalDateTime end = refTime.plusDays(60);
        // 招领物品按捡到时间过滤，寻物物品按丢失时间过滤
        if (ItemConstants.Type.FOUND.equals(targetType)) {
            wrapper.between(Item::getFoundTime, start, end);
        } else {
            wrapper.between(Item::getLostTime, start, end);
        }
    }
}
```

### 3.3 时间窗口说明

- **时间窗口范围**：±60天
- **参考时间**：
  - 寻物启示(LOST)：以 `lostTime`（丢失时间）为参考
  - 失物招领(FOUND)：以 `foundTime`（捡到时间）为参考

## 4. 加权评分算法

### 4.1 评分维度与权重

系统采用**6维度加权评分机制**，每个维度有不同的权重：

| 序号 | 评分维度 | 权重 | 说明 |
|------|----------|------|------|
| 1 | 文本相似度 | 35% | 标题+描述+地点的文本相似度 |
| 2 | 类别匹配 | 25% | 物品类别是否一致 |
| 3 | 地点匹配 | 15% | 丢失/捡到地点是否接近 |
| 4 | 品牌匹配 | 10% | 物品品牌是否一致 |
| 5 | 颜色匹配 | 5% | 物品颜色是否一致 |
| 6 | 时间接近度 | 10% | 丢失时间与捡到时间的接近程度 |

**权重分配公式**：

```
总分 = 文本得分×0.35 + 类别得分×0.25 + 地点得分×0.15 + 品牌得分×0.10 + 颜色得分×0.05 + 时间得分×0.10
```

### 4.2 匹配阈值

- **高分阈值(MATCH_THRESHOLD)**：0.65（65%）
- **高置信度阈值(HIGH_CONFIDENCE_MATCH_THRESHOLD)**：0.80（80%）

当总分 ≥ 0.65 时，认为存在有效匹配，生成匹配记录。

### 4.3 评分细则

#### 4.3.1 文本相似度得分 (35%)

**计算方法**：Dice系数（Dice Coefficient）

**公式**：
```
Dice = 2 × |A ∩ B| / (|A| + |B|)
```
- A：物品1的Token集合
- B：物品2的Token集合
- Token由标题、描述、地点文本生成

**特殊情况**：
- 文本为空时，默认得分 0.5

#### 4.3.2 类别匹配得分 (25%)

| 匹配情况 | 得分 |
|----------|------|
| 完全一致 | 1.0 |
| 互相包含（如"电子产品"包含"手机"） | 0.8 |
| 不匹配 | 0 |

#### 4.3.3 地点匹配得分 (15%)

| 匹配情况 | 得分 |
|----------|------|
| 地点ID完全相同 | 1.0 |
| 地点ID不同，文本相似度 > 0 | 文本相似度 × 0.8 |
| 地点ID不同，文本也完全不同 | 0.5 |

#### 4.3.4 品牌匹配得分 (10%)

| 匹配情况 | 得分 |
|----------|------|
| 完全一致 | 1.0 |
| 互相包含 | 0.8 |
| 部分相似 | 文本相似度 × 0.7 |
| 完全不同或一方为空 | 0.5 |

#### 4.3.5 颜色匹配得分 (5%)

| 匹配情况 | 得分 |
|----------|------|
| 归一化后完全一致 | 1.0 |
| 其他情况 | 0 |

**颜色归一化**：统一转为小写并去除空格，如 "深蓝色" → "深蓝色"，"深蓝" → "深蓝"

#### 4.3.6 时间接近度得分 (10%)

**计算方法**：指数衰减函数

**公式**：
```
score = e^(-|Δdays| / τ)
```
- Δdays：丢失时间与捡到时间的天数差
- τ (tau)：半衰期 = 10天

**得分示例**：

| 时间差 | 得分 |
|--------|------|
| 0天 | 1.00 |
| 10天 | 0.37 |
| 20天 | 0.14 |
| 30天 | 0.05 |
| 60天 | 0.002 |

### 4.4 序列号特殊处理

#### 精确匹配

当寻物启示和失物招领的序列号完全一致时（不区分大小写），直接返回满分 **1.00**，跳过加权评分。

```java
if (hasSerialMatch(lostType, foundType)) {
    log.info("串号精确匹配: lost={}, found={}",
             lostType.serialNumber, foundType.serialNumber);
    return new BigDecimal("1.00");
}
```

#### 序列号冲突

当寻物启示填写了序列号，但失物招领的序列号不一致时，给予**40%惩罚**：

```java
if (hasSerialConflict) {
    totalScore = totalScore.multiply(SERIAL_CONFLICT_PENALTY).setScale(2, RoundingMode.HALF_UP);
    // SERIAL_CONFLICT_PENALTY = 0.40
}
```

## 5. 核心算法实现

### 5.1 MatchingEngine 匹配引擎

核心类位置：`com.campus.lostfound.modules.match.service.impl.MatchingEngine`

#### 5.1.1 评分计算主方法

```java
public BigDecimal calculateScore(LostItem lostType, FoundItem foundType) {
    // 1. 序列号精确匹配检测
    if (hasSerialMatch(lostType, foundType)) {
        return new BigDecimal("1.00");
    }

    // 2. 检测序列号冲突（有序列号但不一致）
    boolean hasSerialConflict = hasSerialConflict(lostType, foundType);

    // 3. 计算各维度得分
    BigDecimal categoryScore = calculateCategoryScore(lostType.category, foundType.category);
    BigDecimal locationScore = calculateLocationScore(
        lostType.locationId, lostType.locationText,
        foundType.locationId, foundType.locationText);
    BigDecimal brandScore = calculateBrandScore(lostType.brand, foundType.brand);
    BigDecimal colorScore = calculateColorScore(lostType.color, foundType.color);
    BigDecimal timeScore = calculateTimeScore(lostType.lostTime, foundType.foundTime);
    BigDecimal textScore = calculateTextScore(lostType, foundType);

    // 4. 加权求和
    BigDecimal totalScore = WEIGHT_TEXT.multiply(textScore)
            .add(WEIGHT_CATEGORY.multiply(categoryScore))
            .add(WEIGHT_LOCATION.multiply(locationScore))
            .add(WEIGHT_BRAND.multiply(brandScore))
            .add(WEIGHT_COLOR.multiply(colorScore))
            .add(WEIGHT_TIME.multiply(timeScore))
            .setScale(2, RoundingMode.HALF_UP);

    // 5. 序列号冲突惩罚
    if (hasSerialConflict) {
        totalScore = totalScore.multiply(SERIAL_CONFLICT_PENALTY).setScale(2, RoundingMode.HALF_UP);
    }

    // 6. 判断是否达到匹配阈值
    if (totalScore.compareTo(MATCH_THRESHOLD) >= 0) {
        return totalScore;
    }

    return BigDecimal.ZERO;
}
```

#### 5.1.2 文本分词算法

本系统采用**中英文混合分词**，支持：

- **英文分词**：按非字母数字字符分割，长度≥2的词作为Token
- **中文分词**：基于bigram（相邻汉字组合）分割

```java
private Set<String> tokenize(String text) {
    if (text == null || text.isBlank()) {
        return Set.of();
    }

    // 归一化：转小写，合并空格
    String normalized = normalizeText(text);
    Set<String> tokens = new HashSet<>();

    // 英文Token：按非字母数字字符分割
    for (String word : normalized.split("[^a-z0-9]+")) {
        if (word.length() >= 2) {
            tokens.add(word);
        }
    }

    // 中文Bigram：相邻汉字组合
    String han = normalized.replaceAll("[^\\p{IsHan}]+", "");
    for (int i = 0; i + 1 < han.length(); i++) {
        tokens.add(han.substring(i, i + 2));
    }

    return tokens;
}
```

**分词示例**：

| 输入文本 | 英文Token | 中文Bigram |
|----------|-----------|------------|
| "校园失物招领平台" | - | 校园、园失、失物、物招、招领、领平、平台 |
| "iPhone 15 Pro Max" | iphone, pro | - |
| "华为Mate60手机" | 华为, mate, 手机 | 华为、为M、Mate、ate6... |

#### 5.1.3 时间衰减算法

```java
private BigDecimal calculateTimeScore(LocalDateTime lostTime, LocalDateTime foundTime) {
    if (lostTime == null || foundTime == null) {
        return new BigDecimal("0.5");  // 时间未知，默认0.5
    }

    // 计算天数差（取绝对值）
    long daysBetween = Math.abs(
        Duration.between(lostTime, foundTime).toDays()
    );

    // 指数衰减：半衰期τ=10天
    double tau = 10.0;
    double score = Math.exp(-daysBetween / tau);

    return BigDecimal.valueOf(score).setScale(2, RoundingMode.HALF_UP);
}
```

### 5.2 匹配分数计算示例

**场景**：用户丢失了一部"黑色华为Mate60手机"

**候选物品**：捡到一部"深蓝色华为Mate60手机"

**评分计算**：

| 维度 | 寻物信息 | 招领信息 | 得分 | 权重 | 加权得分 |
|------|----------|----------|------|------|----------|
| 文本 | "华为Mate60手机 黑色" | "华为Mate60手机 深蓝色" | 0.85 | 0.35 | 0.2975 |
| 类别 | 手机 | 手机 | 1.0 | 0.25 | 0.2500 |
| 地点 | 图书馆 | 图书馆 | 1.0 | 0.15 | 0.1500 |
| 品牌 | 华为 | 华为 | 1.0 | 0.10 | 0.1000 |
| 颜色 | 黑色 | 深蓝色 | 0 | 0.05 | 0 |
| 时间 | 1月15日丢失 | 1月16日捡到 | 0.90 | 0.10 | 0.0900 |

**总分**：0.2975 + 0.25 + 0.15 + 0.10 + 0 + 0.09 = **0.8875**

**结论**：0.8875 > 0.65，匹配成功！

## 6. 匹配类型与状态

### 6.1 匹配类型

| 类型 | 值 | 说明 | 触发条件 |
|------|------|------|----------|
| 精确匹配 | `SERIAL_EXACT` | 序列号100%一致 | 序列号完全相同 |
| 加权匹配 | `WEIGHTED` | 多维度加权评分 | 综合得分 ≥ 0.65 |
| 无匹配 | `NONE` | 不生成匹配记录 | 综合得分 < 0.65 |

### 6.2 匹配状态

| 状态 | 值 | 说明 |
|------|------|------|
| 待确认 | `PENDING` | 匹配已生成，等待用户确认 |
| 已确认 | `CONFIRMED` | 用户确认匹配，物品已归还/找到 |
| 已拒绝 | `REJECTED` | 用户拒绝该匹配 |

```java
@Override
@Transactional
public void matchAll() {
    // 获取所有已审核物品
    LambdaQueryWrapper<Item> wrapper = new LambdaQueryWrapper<>();
    wrapper.eq(Item::getStatus, ItemConstants.Status.APPROVED);
    List<Item> items = itemRepository.selectList(wrapper);

    // 两两匹配
    for (int i = 0; i < items.size(); i++) {
        for (int j = i + 1; j < items.size(); j++) {
            Item item1 = items.get(i);
            Item item2 = items.get(j);

            // 仅匹配不同类型的物品
            if (!item1.getType().equals(item2.getType())) {
                BigDecimal score = calculateScore(item1, item2);
                saveMatch(item1, item2, score);
            }
        }
    }
}
```

## 9. 技术亮点

### 9.1 中英文混合分词

本系统的分词算法同时支持：

- **英文Token提取**：通过正则表达式分割，提取长度≥2的有效词
- **中文Bigram提取**：将中文字符串按相邻汉字组合成2-gram

这种方法的优势：
- 无需引入额外的中文分词库（如IK、jieba）
- 实现简单高效，内存占用低
- 对校园失物招领场景足够实用

### 9.2 Dice系数文本相似度

使用Dice系数计算文本相似度：

```
Dice = 2 × |A ∩ B| / (|A| + |B|)
```

Dice系数的优势：
- 计算简单，效率高
- 取值范围 [0, 1]，直观易懂
- 对文本长度不敏感

### 9.3 指数衰减时间评分

使用指数衰减函数计算时间接近度：

```
score = e^(-|Δdays| / τ)
```

优势：
- 衰减速度可调节（通过半衰期τ）
- 符合人类对时间接近度的直觉感知
- 避免线性衰减的突兀感

### 9.4 BigDecimal精确计算

所有分数计算使用 `BigDecimal` 类型：

```java
BigDecimal totalScore = WEIGHT_TEXT.multiply(textScore)
        .add(WEIGHT_CATEGORY.multiply(categoryScore))
        .add(WEIGHT_LOCATION.multiply(locationScore))
        .add(WEIGHT_BRAND.multiply(brandScore))
        .add(WEIGHT_COLOR.multiply(colorScore))
        .add(WEIGHT_TIME.multiply(timeScore))
        .setScale(2, RoundingMode.HALF_UP);
```

优势：
- 避免Java `float/double` 的精度问题
- 保证金融级计算准确性
- 支持四舍五入模式控制

### 9.5 序列号精确匹配优先

当物品填写了序列号（IMEI、序列号等）时：
- 精确匹配直接返回满分 1.00
- 冲突检测给予40%惩罚

这是针对**电子产品、证件**等有唯一标识物品的优化。

## 10. 使用指南

### 10.1 用户端使用

1. **发布寻物启示**：
   - 填写物品信息（类别、地点、时间、品牌、颜色等）
   - 如有序列号（IMEI），务必填写
   - 系统自动匹配可能的失物招领信息

2. **发布失物招领**：
   - 填写捡到物品的详细信息
   - 系统自动匹配可能的寻物启示

3. **查看匹配结果**：
   - 在"我的匹配"页面查看推荐匹配
   - 点击查看详情
   - 确认或拒绝匹配

### 10.2 管理端使用

1. **手动触发全量匹配**：
   - 调用 `POST /api/matches/match-all`
   - 系统将对所有已审核物品进行两两匹配

2. **查看匹配统计**：
   - 在仪表盘查看匹配成功次数
   - 分析匹配成功率趋势

### 10.3 API接口

| 接口 | 方法 | 说明 |
|------|------|------|
| `/api/matches/item/{itemId}` | GET | 获取物品的匹配列表 |
| `/api/matches/all` | GET | 获取所有匹配记录 |
| `/api/matches/user` | GET | 获取当前用户的匹配记录 |
| `/api/matches/{matchId}/confirm` | POST | 确认匹配 |
| `/api/matches/{matchId}/reject` | POST | 拒绝匹配 |
| `/api/matches/match-all` | POST | 触发全量匹配（管理员） |
